# 第1章 Ollama 与本地 AI 生态

> **版本基线**：Ollama 0.17.x（本文写作时实测 0.17.7）
> **本章定位**：从「聊天玩具」到「Agent 时代的本地模型底座」，认识 Ollama 在本地 AI 生态中的位置

## 引言

> "Get up and running with large language models locally." —— Ollama 官方

### 0.1 先别管术语：Ollama 到底是个啥？

如果你完全没接触过本地大模型，只需要记住三句话：

- **Ollama 是一个"模型管家"**——像应用商店管理 App 一样，一条命令就能下载、运行、切换各种开源大模型；
- **模型 = 一个"聪明大脑"文件**——Ollama 帮你把几 GB 到几十 GB 的模型文件下载到本地，不用自己折腾复杂的配置；
- **一切都在你自己的电脑上**——数据不上传、断网也能用、隐私绝对安全。

打个比方：自己部署大模型过去像"自己组装电脑"（要配 Python 环境、装深度学习框架、处理 GPU 驱动……），而用 Ollama 像是"买品牌机"——开箱即用，一条命令的事。

### 0.2 它这几年经历了什么（简要）

Ollama 仓库创建于 2023 年 6 月 26 日。短短几年，它从一个"本地跑通大模型的命令行工具"，成长为**本地 AI 基础设施的事实标准**：

- 2024 年，Ollama 成为本地部署大模型的首选工具，教程、框架、IDE 插件纷纷接入；
- 2025 年 11 月，本项目（handy-ollama）被 [Ollama 官方仓库](https://github.com/ollama/ollama#tutorial)收录为**唯一的 Tutorial**；
- 2026 年，Agent 工具（Claude Code、Codex CLI、DeepSeek Harness 等）全面爆发，Ollama 顺势推出了 `ollama launch` 一键集成机制，成为这些 Agent 工具对接本地模型的**官方入口**。

### 0.3 本教程讲什么

本教程（全新改版）**从零开始**：先学会"怎么把模型跑起来"（第1~3章），再深入"怎么让本地模型成为可靠、好用的 Agent 后端"（第4~12章）：

> **当 Agent 成为主流交互形态时，怎么让本地模型成为可靠、好用的模型后端？**

本章先建立全局认知：Ollama 是什么、能做什么、支持哪些模型、以及最重要的——**在 Agent 场景下如何选型**。

## 一、Ollama 简介

Ollama 是一个开源的大模型本地运行与管理工具，旨在让用户在消费级硬件上快速启动、运行和部署开源大语言模型。它提供：

- **简洁的 CLI**：`ollama run <模型名>` 一条命令开始对话；
- **本地 HTTP 服务**：默认监听 `localhost:11434`，提供 REST API 与 OpenAI 兼容接口；
- **模型即文件的管理模型**：模型权重、配置、提示词模板打包成统一的 Modelfile，一键下载、切换、定制；
- **自动硬件调度**：优先使用 GPU（NVIDIA / AMD / Apple Silicon），无 GPU 时自动回退 CPU。

### 1.1 下载与安装入口

| 平台 | 方式 | 说明 |
|---|---|---|
| macOS | `curl -fsSL https://ollama.com/install.sh \| sh` | 或下载 Ollama.dmg |
| Windows | `irm https://ollama.com/install.ps1 \| iex` | 或下载 OllamaSetup.exe |
| Linux | `curl -fsSL https://ollama.com/install.sh \| sh` | 支持 systemd 服务 |
| Docker | `docker run -d -v ollama:/root/.ollama -p 11434:11434 ollama/ollama` | 官方镜像 |

详细安装步骤见[第2章](C2)。

### 1.2 一条命令跑起模型

```bash
ollama run qwen3
```

首次运行会自动下载模型（通常为 4~8 GB），之后即进入交互式对话。退出对话使用 `/bye`。

Ollama 会自动检测硬件：有 GPU 时优先 GPU 推理，无 GPU 时使用 CPU。这也是它"消费级硬件友好"的根本原因——底层的推理引擎是著名的 [llama.cpp](https://github.com/ggml-org/llama.cpp) 项目，对 CPU、内存、低显存环境做了深度优化。

## 二、Ollama 核心特性（2026 视角）

上文介绍了 Ollama 的基本能力。本节站在 Agent 场景重新审视，以下能力**决定了本地模型能否作为 Agent 后端**：

### 2.1 Tool Calling（工具调用）—— Agent 的基石

Agent 的本质是"模型 + 工具 + 循环"。模型必须先学会**输出结构化的工具调用请求**，Agent 才能执行工具并把结果反馈给模型。Ollama 从 0.4 版本起原生支持 Tool Calling，模型在请求中声明可用工具，返回结构化的 `tool_calls`。

下面是一个真实可复现的示例（模型：`qwen3:8b`，Ollama 0.17.7）：

```bash
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3:8b",
  "messages": [{"role": "user", "content": "北京今天天气怎么样?"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询指定城市的天气",
      "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "城市名"}},
        "required": ["city"]
      }
    }
  }],
  "stream": false
}'
```

模型不再直接回答"我不知道"，而是返回：

```json
{
  "message": {
    "role": "assistant",
    "tool_calls": [{
      "id": "call_cgbvilmb",
      "function": {
        "name": "get_weather",
        "arguments": {"city": "北京"}
      }
    }]
  }
}
```

这就是 Agent 循环的第一步：**模型决定调用工具，参数完全结构化**。Tool Calling 的完整机制见[第4章](C4)与[第7章](C7)。

### 2.2 Embedding（嵌入）—— RAG 的基石

RAG（检索增强生成）需要把文本变成向量。Ollama 原生支持 Embedding 模型：

```bash
curl http://localhost:11434/api/embed -d '{
  "model": "bge-m3",
  "input": ["Ollama 是什么?", "本地大模型部署"]
}'
```

返回 1024 维向量（以 `bge-m3` 为例），可直接接入向量数据库（Chroma、Milvus、Qdrant 等）做相似度检索。**Ollama 可以同时作为 Embedding 后端和 Generation 后端**，一套服务搞定整个 RAG 流程，见[第10章](C10)。

### 2.3 Vision（视觉理解）—— 多模态 Agent

Ollama 支持视觉模型（如 `llama3.2-vision`、`gemma3` 等），对话中可以传入图片 URL 或 base64 图片。多模态 Agent（截图理解、UI 自动化、文档 OCR）可以完全本地化。

### 2.4 `ollama launch`：官方集成入口（2026 新特性）

这是本教程重点关注的能力（2026 年新特性）。Ollama 现在内置了与主流 Agent 工具的一键集成：

```bash
ollama launch claude          # Claude Code × Ollama
ollama launch codex           # Codex CLI × Ollama
ollama launch dsh             # DeepSeek Harness × Ollama
ollama launch opencode        # OpenCode × Ollama
```

每条命令自动完成"本地模型 ↔ Agent 工具"的对接配置。这是官方在 Agent 时代给出的答案：**Ollama 不只跑模型，还负责把模型"装"进各种 Agent 工具**。详细配置见[第9章](C9)。

### 2.5 其他基础能力

| 能力 | 说明 |
|---|---|
| 多平台 | macOS / Windows / Linux / Docker 全支持 |
| 模型库 | [ollama.com/library](https://ollama.com/library) 数千模型，一条命令拉取 |
| Modelfile | 类似 Dockerfile 的模型定制文件，可固化 system prompt、参数、模板 |
| 量化开箱即用 | 下载即量化（Q4_K_M 等），无需手动处理 GGUF |
| OpenAI 兼容接口 | `http://localhost:11434/v1`，任何支持 OpenAI SDK 的框架直接对接 |
| 隐私 | 全部推理在本地完成，数据不出机器 |
| 生态庞大 | LangChain / LlamaIndex / LiteLLM / Spring AI / Open WebUI / Dify / n8n 等均已集成 |

## 三、支持的模型与模型库

Ollama 模型库地址：[https://ollama.com/library](https://ollama.com/library)，支持数千个模型与版本组合，全部一键 `ollama run <模型名>` 拉取。

### 3.1 主流模型一览（2026 年 9 月）

| 模型 | 特点 | Agent 场景适用性 |
|---|---|---|
| **Qwen3 系列**（`qwen3:8b` 等） | 通义千问第三代，原生 Tool Calling，可选思考模式 | ⭐ 本地 Agent 首选：工具调用稳定 |
| **DeepSeek-R1**（`deepseek-r1:7b/8b` 等） | 推理型（Reasoning）模型，擅长数学/逻辑 | 复杂推理任务，注意推理输出较长 |
| **Gemma 系列**（`gemma4`、`gemma3`） | Google 开源，多模态（视觉），轻量高效 | 多模态 + 轻量场景 |
| **Llama 系列**（`llama3.3` 等） | Meta 开源，生态最成熟 | 通用场景，社区资料最多 |
| **Mistral 系列** | 法语/英语通用，工具调用支持好 | 通用 Agent 场景 |

> ⚠️ 模型库更新极快（新模型、新量化版本持续发布）。**本文不保证模型列表的长期准确**，请以 [ollama.com/library](https://ollama.com/library) 为准，并关注本书 `living-docs/changelog.md` 的更新记录。

### 3.2 一个模型名背后的信息

```bash
ollama run qwen3:8b        # 家族:qwen3, 规格:8B 参数, 默认量化
ollama run qwen3:8b-q8_0   # 显式指定 Q8_0 量化
ollama run bge-m3:latest   # 嵌入模型
```

`家族:规格-量化` 三段式命名，其中**量化级别直接决定显存占用与质量**，是 Agent 场景选型的核心变量，详见[第3章](C3)的量化深度解析。

## 四、Agent 场景下的模型选型指南（新增 · 本章核心）

这是本教程的核心新增内容。**聊天场景下"能聊就行"，Agent 场景下模型能力直接决定任务成败**。选型时从四个维度评估：

### 4.1 四个关键维度

**维度一：Tool Calling 能力（最重要）**

Agent 循环依赖模型稳定输出结构化的 `tool_calls`。判断标准：

- 模型家族是否原生支持 Tool Calling（如 Qwen3、Llama 3.1+、Mistral 等）；
- 小参数模型（≤3B）工具调用不稳定，容易出现"该调用工具时不调用、参数格式错误"的问题；
- **建议下限：7B~8B 级别的工具调用模型**（如 `qwen3:8b`）。

**维度二：上下文长度（Context Length）**

Agent 的上下文会快速膨胀：系统提示词 + 工具描述 + 多轮工具结果 + 代码片段。判断标准：

- 长上下文模型（如 `qwen3:8b-64k`，64K）适合代码生成、长文档处理、多轮 Agent 会话；
- 注意：上下文越长，显存/内存占用越高、推理越慢，**不是越长越好**；
- Ollama 中可通过 `num_ctx` 参数控制实际上下文长度，详见[第4章](C4)。

**维度三：推理型 vs 指令型（Reasoning vs Instruction）**

- **指令型**（如 Qwen3 非思考模式）：响应快、token 少，适合大部分工具调用场景；
- **推理型**（如 DeepSeek-R1、Qwen3 思考模式）：先"想"再答，复杂任务准确率高，但输出长、延迟高；
- Agent 场景建议：**默认指令型，复杂任务临时切换到推理型**，或两者组合。

**维度四：硬件预算**

- 显存决定能跑多大的模型与多长的上下文；
- 经验公式：8B 模型 Q4 量化约需 5~6 GB 显存（含 KV cache 余量）；
- 显存不足时优先降量化（Q8_0 → Q4_K_M），而不是降参数规模。

### 4.2 场景速查表

| 场景 | 推荐模型方向 | 理由 |
|---|---|---|
| 通用代码 Agent（Claude Code / Codex 配本地模型） | Qwen3 8B~14B（长上下文变体） | 工具调用稳定 + 代码能力强 |
| 复杂推理（数学/逻辑/规划） | DeepSeek-R1 蒸馏版、Qwen3 思考模式 | 推理型模型逐步推导 |
| 多模态（截图理解、文档 OCR） | Gemma3/Gemma4、llama3.2-vision | 原生视觉能力 |
| 本地 RAG | 生成：Qwen3 系列；嵌入：bge-m3 / nomic-embed-text | 生成+嵌入双后端 |
| 低配机器（4GB 显存以下） | 3B~4B 指令型（qwen3:4b 等） | 显存优先，接受工具调用质量折损 |
| 隐私敏感（本地纯离线） | 任意上述模型 + 关闭遥测 | 数据不出本机 |

### 4.3 用「能力探测」代替「道听途说」

选型不该靠猜。Ollama 暴露了模型的实际能力，可以写一个 5 分钟的能力探测脚本：让模型完成"查询天气→解析返回参数→继续对话"的小任务，观察它能否**连续多轮**正确调用工具。第8章会给出完整的最小 Agent 代码，这里先给出结论：

> **本地实测（本书环境：Ollama 0.17.7 + qwen3:8b-64k）**：单轮工具调用 100% 正确，多轮（3 轮以上）偶发参数遗漏，属正常现象——**本地模型的 Agent 能力边界是"可用但需容错"**。这正是第7章"为什么本地模型在 Agent 场景容易出问题"要展开的主题。

## 五、Ollama 在本地 AI 生态中的位置

本地推理工具众多，理解各自定位有助于选型：

| 工具 | 定位 | 与 Ollama 的关系 |
|---|---|---|
| **Ollama** | 一键部署 + 模型管理 + 标准 API | 本教程主角 |
| **llama.cpp** | C/C++ 推理引擎（底层库） | Ollama 的后端引擎，可单独使用但门槛高 |
| **vLLM** | 高吞吐服务化推理（PagedAttention） | 服务器级替代品，需 GPU，面向高并发 |
| **LM Studio / Jan** | 图形化桌面客户端 | 面向普通用户的可视化替代 |
| **Open WebUI** | 网页聊天界面 | **配合** Ollama 使用（见[第12章](C12)） |
| **LiteLLM** | 统一 API 网关（100+ 提供商） | 可把 Ollama 伪装成任意 OpenAI 端点 |

一句话总结生态位：**llama.cpp 是发动机，Ollama 是整车，Open WebUI 是内饰，LiteLLM 是改装厂，Agent Harness 是驾驶员。** 本教程讲的是：怎么把这台车保养好、加对油，并交给各种驾驶员（Claude Code / Codex / DeepSeek Harness）安全地开。

## 六、本章小结

1. Ollama 已从"本地跑模型工具"升级为 **Agent 时代的本地模型底座**，`ollama launch` 是其官方集成入口；
2. **Tool Calling、Embedding、Vision** 三大能力决定了本地模型能否支撑 Agent 与 RAG 场景；
3. 选型四维度：**工具调用能力 > 上下文长度 > 推理/指令型 > 硬件预算**；
4. 本地模型 Agent 能力"可用但需容错"，后续章节会深入展开。
