# 本地多 Agent 协作：CrewAI + Ollama

> **版本基线**：Ollama 0.17.x + CrewAI（配置方式与[第6章](../C6/4.%20OpenAI%20兼容接口对接任意框架.md)实测的 OpenAI 兼容接口一致）
> **本节定位**：用 CrewAI 编排多个本地模型 Agent 协作完成复杂任务
> **代码**：`notebook/C11/`

## 一、多 Agent 协作是什么

单 Agent 做"调研 + 写报告 + 校对"这种复合任务时，上下文混杂、角色不清。多 Agent 协作的思路是**分工**：

```
用户: 写一份本地大模型部署方案
   │
   ▼
┌────────────────────────────────────────────┐
│ 研究 Agent(研究员角色)                        │
│   任务: 调研硬件需求与模型选型                  │
│   产出: 调研报告片段                          │
└────────────────┬───────────────────────────┘
                 ▼
┌────────────────────────────────────────────┐
│ 写作 Agent(作家角色)                         │
│   任务: 基于调研结果撰写方案正文                │
└────────────────┬───────────────────────────┘
                 ▼
┌────────────────────────────────────────────┐
│ 校对 Agent(审稿角色)                         │
│   任务: 检查遗漏与格式, 输出终稿               │
└────────────────────────────────────────────┘
```

每个 Agent 有**独立的角色设定、任务描述与上下文**，通过消息传递接力。

## 二、CrewAI 是什么,为什么选它

**CrewAI** 是 2023 年底开源的 Python 多 Agent 编排框架,把「多角色协作」建模成**团队协作**:Agent 是带角色/目标/背景的成员,Task 是分给他们的活,Crew 是把成员和任务编成一组的团队。它用自然语言定义角色,约 20 行代码就能跑起一个多 Agent 流水线。

本书选它讲多 Agent(2026 年视角):

- **入门门槛最低**：只有 Agent / Task / Crew 三个概念,对应「员工 / 工单 / 团队」——先学会「协作怎么分工」,而不是先啃图论；
- **社区最活跃**：多 Agent 框架中社区规模与活跃度最高,教程、案例、工具链最全,遇到问题容易找到答案；
- **模型无关、天然适配本地**：通过 OpenAI 兼容接口直接接 Ollama(下文演示),不绑定任何云端模型；
- **市场格局验证**：同期选手要么热度不再——AutoGen 已在 2026 年并入 Microsoft Agent Framework、进入维护模式,OpenAI Swarm 已被官方废弃;要么不适合本书主题——OpenAI/Claude/Google 的厂商 SDK 深度绑定自家云模型,与「纯本地 Ollama」不符。

想要更精细的流程控制（条件分支、循环、状态管理）,看 [10.2 LangGraph](./2.%20LangGraph%20多%20Agent%20协作.md)——它是生产级选择,但学习曲线更高:先学 CrewAI 建立心智模型,再上 LangGraph 控制细节。

## 三、CrewAI 核心概念

| 概念 | 说明 | 类比 |
|---|---|---|
| **Agent** | 带角色/目标/背景的智能体 | 员工 |
| **Task** | 交给 Agent 的具体任务 | 工单 |
| **Crew** | Agent + Task 的编排组合 | 团队 |
| **Process** | 顺序/层级执行方式 | 工作流 |

## 四、接入本地模型

CrewAI 通过 LangChain 的 LLM 对象接入模型。用 OpenAI 兼容接口指向本地 Ollama（与第 6 章实测的写法完全一致）：

```python
from langchain_openai import ChatOpenAI

local_llm = ChatOpenAI(
    base_url="http://localhost:11434/v1",   # 本地 Ollama
    api_key="ollama",
    model="qwen3:8b",
    temperature=0.2,
)
```

## 五、完整示例：双 Agent 写作团队

```python
from crewai import Agent, Task, Crew, Process
from langchain_openai import ChatOpenAI

local_llm = ChatOpenAI(base_url="http://localhost:11434/v1",
                       api_key="ollama", model="qwen3:8b")

# 1. 研究员
researcher = Agent(
    role="技术研究员",
    goal="调研本地大模型部署的关键要点",
    backstory="你是资深的 AI 基础设施工程师, 擅长提炼要点。",
    llm=local_llm,
)

# 2. 写作员
writer = Agent(
    role="技术文档作者",
    goal="把调研要点写成结构清晰的方案文档",
    backstory="你是技术写作专家, 擅长把要点组织成易读文档。",
    llm=local_llm,
)

research_task = Task(
    description="调研本地部署大模型需要关注的 5 个要点(硬件/模型/工具/风险/成本)",
    agent=researcher,
    expected_output="5 个要点, 每条一句话",
)

write_task = Task(
    description="基于调研结果撰写 200 字的部署方案概述",
    agent=writer,
    expected_output="200 字左右的方案概述",
)

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.sequential,   # 顺序执行
)

result = crew.kickoff(inputs={"topic": "本地大模型部署"})
print(result)
```

## 六、本地模型做多 Agent 的注意点

1. **每个 Agent 都是独立上下文**：N 个 Agent = N 份上下文同时占用显存/内存。3 个 8B 模型同时驻留，显存需求约为单模型的 3 倍（含 KV cache）——先看[3. 本地模型资源调度](./3.%20本地模型资源调度.md)；
2. **任务接力靠文本**：Agent 之间传递的是纯文本产出，传递内容越长，下游 Agent 上下文越紧张——**要求每步输出精简**（`expected_output` 写清楚长度）；
3. **质量依赖模型能力**：8B 模型扮演"角色"的能力有限，角色设定要简单直接，复杂分工建议用更大的模型或云端；
4. **速度放大**：顺序流程中每个 Agent 都要完整推理一轮，总耗时 ≈ 单 Agent 耗时 × Agent 数——**减少 Agent 数量、精简任务**。

## 本节小结

- 为什么是 CrewAI：入门门槛最低（Agent/Task/Crew 三概念）、社区最活跃、模型无关可直连本地 Ollama——2026 年多 Agent 框架格局验证了这一选择（AutoGen 进维护模式、厂商 SDK 绑定云模型）；
- CrewAI 用 Agent/Task/Crew 三件套实现分工协作，LangChain LLM 对象接入本地模型；
- OpenAI 兼容接口（base_url → `/v1`）是 CrewAI × Ollama 的标准接法；
- 本地多 Agent 三大成本：显存 ×N、文本接力、耗时 ×N——按需精简。
