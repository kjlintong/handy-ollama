# Ollama 安装与配置 - GPU / CPU 混合推理配置

> **版本基线**：Ollama 0.17.x
> **本章定位**：理解 Ollama 的硬件调度机制，掌握 GPU/CPU 混合推理配置，为第 11 章「多模型资源调度」打基础

## 一、Ollama 的硬件调度机制

Ollama 启动模型时的默认策略是**自动检测**：

1. 检测到 GPU（NVIDIA / AMD / Apple Silicon）→ 优先将模型**全部层**加载到 GPU 推理；
2. 显存装不下整个模型 → 自动把装不下的层放到 CPU 计算（**混合推理**）；
3. 完全没有 GPU → 纯 CPU 推理（第一期教程的经典场景）。

现代大模型都是**多层 Transformer 架构**，Ollama 以「层」为单位在 GPU/CPU 间分配计算。判断当前模型实际跑在什么硬件上，用：

```bash
ollama ps
```

输出中的 `PROCESSOR` 列会明确告诉你分配情况：

```
NAME            ID              SIZE      PROCESSOR         UNTIL
qwen3:8b-64k    xxxxxxxxxxxx    5.5 GB    100% GPU          4 minutes from now
qwen3:8b-64k    xxxxxxxxxxxx    5.5 GB    67% GPU/33% CPU   4 minutes from now
```

`100% GPU` 表示完全 GPU 推理；`67% GPU/33% CPU` 表示混合推理（部分层在 CPU）。

## 二、什么时候需要手动配置

自动调度在大多数情况下已经足够，但以下场景需要手动干预：

| 场景 | 症状 | 手段 |
|---|---|---|
| 显存不足导致模型装不下 | 模型加载失败或全部掉到 CPU | 减小量化、缩短上下文、或用 `num_gpu` 指定 GPU 层数 |
| 显存有富余但想并发加载多个模型 | 换模型时反复重新加载 | `OLLAMA_MAX_LOADED_MODELS` 提升并发加载数 |
| 模型加载/卸载太频繁 | 每次请求都有明显延迟 | `OLLAMA_KEEP_ALIVE` 延长驻留时间 |
| 多 GPU 想指定用哪块卡 | 模型默认只用了第一块卡 | `CUDA_VISIBLE_DEVICES` 指定 GPU |
| 长上下文场景显存紧张 | 上下文一长就 OOM | `OLLAMA_FLASH_ATTENTION` + `OLLAMA_KV_CACHE_TYPE` |

## 三、核心配置详解

### 3.1 指定 GPU 层数（混合推理比例）

Ollama 默认尽量把层加载到 GPU。若想手动控制"多少层在 GPU、多少层在 CPU"，有两种方式：

**方式一：Modelfile 中固化（推荐，随模型走）**

```
FROM qwen3:8b
PARAMETER num_gpu 20
```

`num_gpu` 表示发送到 GPU 的层数（-1 = 全部层，0 = 全部 CPU）。创建后该模型永久使用该配置。

**方式二：API 请求中临时指定**

```bash
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3:8b",
  "messages": [{"role": "user", "content": "你好"}],
  "options": {"num_gpu": 20},
  "stream": false
}'
```

> 注：环境变量 `OLLAMA_NUM_GPU`（历史版本支持，设置全局 GPU 层数）在新版文档中已不再推荐，统一用 Modelfile / API 的 `num_gpu` 参数更精确。

### 3.2 并发加载多个模型（Agent 场景常用）

默认 Ollama 最多同时加载 **3 × GPU 数量** 个模型（纯 CPU 推理时为 3 个），前提是内存放得下。多 Agent 场景（见[第11章](../C11)）需要同时驻留对话模型 + 嵌入模型时：

```bash
# Linux/macOS: 启动前设置
export OLLAMA_MAX_LOADED_MODELS=4
ollama serve

# Windows: 设置系统环境变量 OLLAMA_MAX_LOADED_MODELS=4 后重启 Ollama
```

### 3.3 控制模型驻留时间（KEEP_ALIVE）

Agent 会话中模型反复加载会拖慢响应。默认模型处理完请求后驻留 **5 分钟**：

```bash
# 驻留 24 小时
export OLLAMA_KEEP_ALIVE=24h
# 永不卸载
export OLLAMA_KEEP_ALIVE=-1
```

也可以在 API 请求中用 `keep_alive` 字段对单次请求覆盖（`keep_alive: 0` 表示用完立即卸载，适合显存紧张时）。

### 3.4 长上下文的内存优化

长上下文 Agent 场景（如 64K 上下文）KV cache 会吃掉大量显存，两个关键开关：

```bash
# 开启 Flash Attention（现代模型默认自动开启，可强制）
export OLLAMA_FLASH_ATTENTION=1
# KV cache 量化，从 f16 降到 q8_0，显著省显存
export OLLAMA_KV_CACHE_TYPE=q8_0
```

### 3.5 多 GPU 选择

```bash
# 查看 GPU UUID
nvidia-smi -L
# 指定使用某块卡（Linux/macOS）
export CUDA_VISIBLE_DEVICES=0,1
```

## 四、实测验证流程

配置完成后，按以下顺序验证：

```bash
# 1. 确认 Ollama 识别到 GPU
ollama run qwen3:8b "nvidia-smi 里能看到 ollama 进程吗?"  # 或直接看 nvidia-smi
nvidia-smi

# 2. 加载模型
ollama run qwen3:8b

# 3. 另一个终端查看分配
ollama ps
# PROCESSOR 列: 100% GPU / 67% GPU/33% CPU / 100% CPU

# 4. 压测观察吞吐(简单计时)
time curl -s http://localhost:11434/api/generate -d '{"model":"qwen3:8b","prompt":"1+1=?","stream":false}' > /dev/null
```

## 五、故障速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `ollama ps` 显示 100% CPU | 显存不足自动回退 | 换更小量化（见[第3章](../C3)），或减少 `num_ctx` |
| 模型加载报 "insufficient memory" | 显存 + 内存都不够 | 换小模型，或 `keep_alive: 0` 及时释放 |
| 换模型后响应变慢 | 模型被卸载重新加载 | `OLLAMA_KEEP_ALIVE` 调大 |
| 两块 GPU 只用了一块 | 未配置 | `CUDA_VISIBLE_DEVICES` 指定 |
| GPU 显存占用异常高 | KV cache 过大 | `OLLAMA_KV_CACHE_TYPE=q8_0` + Flash Attention |

更多排查见 [living-docs/troubleshooting.md](../../living-docs/troubleshooting.md)。
