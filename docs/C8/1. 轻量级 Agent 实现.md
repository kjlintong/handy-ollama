# 轻量级 Agent 实现：100 行极简 Agent

> **版本基线**：Ollama 0.17.x + ollama-python 0.6.x（本章示例实测通过）
> **章节定位**：动手写一个 100 行的极简 Agent，把第 7 章的原理变成能跑的真代码。**目的是理解，不是生产**——下一节展示如何用成熟 Harness 替代它。
> **代码**：`notebook/C8/mini_agent.py`

## 一、目标与设计

我们要写一个能**解析指令、调用工具**的极简 Agent，三个内置工具：

| 工具 | 功能 | 说明 |
|---|---|---|
| `get_weather(city)` | 查城市天气 | 模拟数据，演示工具调用 |
| `calculator(expr)` | 数学计算 | 演示参数解析与安全限制 |
| `read_file(path)` | 读本地文件 | 演示真实副作用工具 |

设计要点（对应第 7 章原理）：

- **ReAct 循环**：最多 6 轮，模型调用工具 → 执行 → 回传 → 直到给出最终回答；
- **工具注册表**：`TOOLS`（给模型的 JSON Schema）+ `FUNCS`（给程序的实际函数）分离；
- **系统提示词**：明确"需要外部信息时调用工具"；
- **错误回传**：工具抛异常时把错误信息回传模型，让它自我修正。

## 二、核心代码（约 100 行）

### 2.1 工具实现与注册

```python
import ollama

client = ollama.Client(host=os.environ.get("OLLAMA_HOST", "http://localhost:11434"))

def get_weather(city: str) -> str:
    """查询指定城市今天的天气。city: 城市名"""
    return f"{city}: {WEATHER.get(city, '暂无数据')}"

def calculator(expr: str) -> str:
    """计算数学表达式, 如 '2*3+4'。expr: 数学表达式字符串"""
    expr = re.sub(r"[^0-9+\-*/().\s]", "", expr)   # 白名单过滤, 防注入
    return str(eval(expr))                          # 教学简化; 生产请用安全库

# TOOLS: 给模型看的"世界说明书" (JSON Schema)
TOOLS = [{"type": "function", "function": {
    "name": "get_weather", "description": get_weather.__doc__,
    "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}}]

# FUNCS: 给程序用的真实函数
FUNCS = {"get_weather": get_weather, "calculator": calculator, "read_file": read_file}
```

### 2.2 ReAct 循环（核心）

```python
def run_agent(task: str) -> None:
    messages = [{"role": "system", "content": SYSTEM},
                {"role": "user", "content": task}]
    for round_no in range(1, MAX_ROUNDS + 1):
        resp = client.chat(model=OLLAMA_MODEL, messages=messages, tools=TOOLS)
        msg = resp.message
        if not msg.tool_calls:                 # 不再调用工具 → 最终回答
            print(f"[模型] {msg.content}")
            return
        messages.append({"role": "assistant", "content": msg.content or "",
                         "tool_calls": msg.tool_calls})   # 原样回传
        for call in msg.tool_calls:
            fn = call.function
            result = FUNCS[fn.name](**fn.arguments or {})  # 分发执行
            print(f"[工具] {fn.name}{fn.arguments} -> {result}")
            messages.append({"role": "tool", "content": str(result)})  # 观察回传
```

**这段 while 循环就是 ReAct 的全部秘密**：模型每轮要么调用工具（继续循环），要么给出回答（结束）。加上 `MAX_ROUNDS` 防止失控。

## 三、实测运行（本书环境：Ollama 0.17.7 + qwen3:8b-64k）

```bash
python notebook/C8/mini_agent.py "帮我查一下北京天气, 然后计算 23*17+9 等于多少"
```

实测输出（真实结果）：

```
===== 第 1 轮 =====
[工具] get_weather{"city": "北京"} -> 北京: 晴, 32°C
[工具] calculator{"expr": "23*17+9"} -> 400

===== 第 2 轮 =====
[模型] 北京今天天气晴，温度32°C。
23*17+9 的计算结果是 400。
```

观察点：

1. **一轮并行调用两个工具**——模型理解"两个子任务互不依赖"，触发并行 tool_calls；
2. **参数完全正确**——`{"city": "北京"}`、`{"expr": "23*17+9"}` 符合 schema；
3. **第二轮基于工具结果合成回答**——没有编造天气和计算结果；
4. **错误也能优雅处理**——当工具返回"文件不存在"，模型如实报告而不是幻觉编造。

## 四、这个 Agent 缺什么（诚实清单）

理解归理解，这个小 Agent 离生产差距明显：

| 缺失能力 | 影响 | 成熟方案 |
|---|---|---|
| 多工具类型（MCP） | 只能调用内置 3 个工具 | MCP 协议（[第5章](../C5)） |
| 会话持久化 | 重启即失忆 | Harness 的 session 管理 |
| 权限控制 | 工具想调就调，无确认 | Harness 的 permission flow |
| 子任务并行/子 Agent | 单线程顺序执行 | 多 Agent 框架（[第11章](../C11)） |
| 流式输出、中断恢复 | 体验差 | Harness 原生支持 |
| 上下文管理 | 长了就爆 | 自动 compact（Harness 内置） |

**结论：原理自己写，生产用 Harness。** 下一节看怎么替换。

## 本章小结

- 100 行代码 = 工具注册表 + ReAct 循环，就能让本地模型成为会调用工具的 Agent；
- 实测验证：并行工具调用、参数正确、结果合成、错误处理全部工作正常；
- 手写 Agent 的价值在于**理解轮子怎么转**，生产场景直接上成熟 Harness。
