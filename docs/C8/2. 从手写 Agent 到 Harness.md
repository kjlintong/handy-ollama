# 从手写 Agent 到 Harness：拥抱成熟工具

> **版本基线**：2026 年 9 月，各 Harness 快速迭代，具体命令以官方文档为准
> **章节定位**：承上启下——理解原理后，把手写 Agent 替换为成熟 Harness（Claude Code / Codex CLI / DeepSeek Harness），并说明为什么这是正确选择

## 一、为什么要换掉手写 Agent

上一节的 100 行 Agent 证明了原理，但生产环境需要的能力它都没有：权限控制、会话管理、上下文压缩、多工具生态、中断恢复……

**成熟的 Harness（Agent 外壳）把这些能力全部内置**。它们的设计哲学是：**模型可替换、能力即插即用**——这正是 Ollama 的用武之地：把 Harness 的模型后端换成本地模型，你就同时拥有了"成熟外壳 + 本地模型 + 隐私安全"。

## 二、替换后的架构对比

```
手写 Agent:                       Harness + Ollama:
┌─────────────────┐               ┌──────────────────────────┐
│ 自己写的 100 行循环 │               │  Harness (成熟外壳)        │
│ 3 个内置工具      │               │  ├─ 权限/会话/上下文管理      │
│ 无持久化/无权限    │               │  ├─ MCP 工具生态            │
└────────┬────────┘               │  └─ 模型后端 = Ollama 本地模型 │
         │ 同一套原理               └────────────┬─────────────┘
    ReAct 循环 / Tool Calling /         ReAct 循环(内置, 你看不见但一样)
    JSON Schema / 消息回传                工具调用(内置, 走 OpenAI/Anthropic 兼容)
```

**原理完全一致**（ReAct 循环、工具调用、消息回传），只是外壳更厚、能力更全。这就是本教程"理解原理 → 拥抱工具"的完整闭环。

## 三、三个主流 Harness 一句话对比

| Harness | 定位 | 与 Ollama 的关系（详见第9章） |
|---|---|---|
| **Claude Code** | 终端里的编码 Agent，生态最成熟 | `ollama launch claude` 即配好本地后端 |
| **Codex CLI** | OpenAI 的轻量编码 Agent | `--oss` 模式原生对接 Ollama |
| **DeepSeek Harness** | DeepSeek 开源 Agent，一切皆插件 | `ollama launch dsh` 官方集成 |

> 三者的详细配置、模型选型、性能边界在[第9章](../C9)逐一展开。

## 四、迁移路径建议

从手写 Agent 平滑迁移到 Harness，推荐三步走：

**第 1 步：确定模型（最重要）**
- 用第 1 章的选型指南 + 第 8 章实测脚本，确定你的本地模型（工具调用稳定性是硬指标）；
- 建议起步：`qwen3:8b`（工具调用稳定、显存友好）。

**第 2 步：选一个 Harness 跑通**
- 从 Claude Code 或 Codex CLI 开始（资料最多）；
- 完成"本地模型 + 读代码 + 改文件 + 跑命令"的最小闭环；
- 感受性能边界：多步任务的等待时间、长上下文的处理。

**第 3 步：按需增强**
- 接 MCP Server 扩展工具（第 5 章）；
- 混合策略：复杂任务切云端模型、敏感任务用本地模型（第 9 章）；
- 多 Agent 与资源调度（第 11 章）。

## 五、什么时候继续用手写方案

不是所有场景都该上 Harness：

- **嵌入式/受限环境**：无法安装 Node.js 等运行时 → 手写轻量 Agent 是唯一选择；
- **固定流水线**：任务形态固定（如定时抓数据 → 调模型 → 写报告），手写脚本更可控；
- **教学与实验**：理解原理、快速验证模型能力，100 行足够。

## 本章小结

- 手写 Agent 的价值在**理解原理**，生产的价值在**成熟外壳**；
- Harness 与手写方案基于同一套原理，替换成本低、收益大；
- 迁移三步：定模型 → 跑通最小闭环 → 按需增强；
- 嵌入式/固定流水线/教学场景，手写方案依然合理。
