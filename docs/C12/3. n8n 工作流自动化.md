# n8n 工作流自动化 × Ollama

> **版本基线**：Ollama 0.17.x + n8n（配置以官方集成文档为准）
> **章节定位**：把本地模型嵌入自动化工作流——定时任务、消息触发、数据管道都能接 Ollama
> **官方文档**：[https://docs.ollama.com/integrations/n8n](https://docs.ollama.com/integrations/n8n)

## 一、n8n 是什么

n8n 是开源的工作流自动化平台（类似 Zapier 的自托管版）：用可视化画布把「触发器 → 处理节点 → 动作节点」串成自动化流程。

**Ollama 的生态位**：n8n 原生内置 Ollama 节点，本地模型可以作为工作流中的"智能处理步骤"——比如：

- 定时抓取 RSS → Ollama 总结 → 发送到邮箱/IM；
- 收到表单提交 → Ollama 分类/打标 → 写入数据库；
- 监控日志异常 → Ollama 生成处理建议 → 通知值班群。

## 二、对接配置

### 2.1 安装 n8n

```bash
# 方式一: npm 直接运行
npm install -g n8n && n8n start

# 方式二: Docker(推荐, 注意 host.docker.internal)
docker run -it --rm \
  --add-host=host.docker.internal:host-gateway \
  -p 5678:5678 \
  n8nio/n8n
```

### 2.2 添加 Ollama 凭据

1. n8n 右上角 → **Create Credential** → 选择 **Ollama**；
2. Base URL 填写：
   - 本地直接运行 n8n：`http://localhost:11434`
   - Docker 运行 n8n、Ollama 在宿主机：`http://host.docker.internal:11434`
3. 保存后应显示 `Connection tested successfully`。

> Linux 服务器（非 Docker Desktop）没有自动的 `host.docker.internal`，需用 `--add-host=host.docker.internal:host-gateway`（或 compose 的 `extra_hosts`）手动加。

### 2.3 使用 Ollama 节点

新建工作流 → 添加 **Ollama node** → 选择模型（如 `qwen3-coder`、`qwen3:8b`）→ 配置提示词模板。

```
[定时触发器] → [Ollama 节点: 总结 RSS 内容] → [邮件节点: 发送摘要]
```

### 2.4 连接 ollama.com 云端模型（可选）

1. 在 [ollama.com/settings/keys](https://ollama.com/settings/keys) 创建 API Key；
2. n8n 凭据中 API URL 填 `https://ollama.com` + API Key。

## 三、本地模型在 n8n 中的使用要点

1. **长任务要异步**：本地模型推理慢（秒级~分钟级），不要把 Ollama 节点放在需要即时响应的关键路径上；长流程用「等待/轮询」模式；
2. **提示词模板化**：n8n 节点支持模板变量（如 `{{ $json.rss_content }}`），把上游数据拼进提示词——保持模板精简，避免把无关字段塞进上下文；
3. **错误重试**：本地模型偶发超时/格式错误，节点配置「重试 2~3 次」；
4. **并发注意**：多个工作流同时触发会排队（`OLLAMA_NUM_PARALLEL` 可调，见[第11章](../C11/3.%20本地模型资源调度.md)）；
5. **与 Agent 场景结合**：n8n 也支持接入 Agent 节点/自定义工具，可以把第 8 章的 Agent 或 MCP Server 挂进工作流。

## 本章小结

- n8n 原生支持 Ollama 节点，本地模型成为自动化工作流的"智能步骤"；
- 凭据配置三要素：Base URL（`localhost` 或 `host.docker.internal`）、模型名、连接测试；
- 实践要点：异步化长任务、模板精简、错误重试、并发规划。
