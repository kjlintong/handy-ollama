# 9.1 Claude Code × Ollama 集成实战

> **版本基线**：Ollama 0.17.x + Claude Code 2.x（配置以官方集成文档为准，写作时 2026-09）
> **章节定位**：只讲「Ollama 怎么给 Claude Code 当模型后端」，不讲 Claude Code 本身怎么用（边界铁律）
> **官方文档**：[https://docs.ollama.com/integrations/claude-code](https://docs.ollama.com/integrations/claude-code)

## 一、集成原理

Claude Code 通过 **Anthropic 兼容 API** 连接模型。Ollama 原生实现了 Anthropic 兼容端点，因此：

```
Claude Code ──Anthropic 协议──► Ollama(本地模型)
```

这意味着不需要任何插件或中间层，配置三个环境变量即可把 Claude Code 的模型后端整个换成 Ollama——包括 Chat、工具调用、文件编辑、子 Agent 等全部能力（取决于模型是否支持）。

## 二、对接配置

### 方式一：一键（推荐）

```bash
ollama launch claude
```

Ollama 自动安装/连接 Claude Code 并完成配置。指定模型：

```bash
ollama launch claude --model qwen3.5
# 云端模型同样支持
ollama launch claude --model gemma4:cloud
```

### 方式二：手动配置（理解原理）

```bash
# 1. 安装 Claude Code
curl -fsSL https://claude.ai/install.sh | bash   # macOS/Linux
# irm https://claude.ai/install.ps1 | iex        # Windows

# 2. 设置环境变量, 指向本地 Ollama
export ANTHROPIC_AUTH_TOKEN=ollama     # 本地不校验, 任意值
export ANTHROPIC_API_KEY=""            # 必须为空字符串
export ANTHROPIC_BASE_URL=http://localhost:11434

# 3. 启动并指定本地模型
claude --model qwen3.5
```

非交互/CI 场景：

```bash
ollama launch claude --model gemma4:cloud --yes -- -p "这个仓库是干什么的?"
# --yes 跳过交互选择; -- 之后的参数原样传给 Claude Code
```

## 三、本地模型选型建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 通用编码（读代码/改文件/跑命令） | `qwen3.5` 或 `qwen3:8b-64k` | 工具调用稳定 + 长上下文 |
| 小仓库快速体验 | 8B 级模型 | 显存友好、响应够快 |
| 大仓库 | 上下文 ≥64K 的模型 | **官方明确建议 64k+ 上下文窗口**（大仓库检索需要） |
| 视觉任务 | gemma4 等多模态模型 | 截图理解 |

> 模型选择可参考 [ollama.com/search?c=tools](https://ollama.com/search?c=tools)（Ollama 官方筛选的"工具调用友好"模型列表）。

## 四、性能边界提示（实测导向）

1. **上下文长度是第一瓶颈**：Claude Code 会话会累积大量上下文（系统提示 + 工具结果 + 代码片段），本地 8K/16K 模型很快触顶。**起步就用 64K 上下文模型**，或通过 `num_ctx` 显式配置；
2. **推理速度决定体验**：本地 8B 模型约 20~60 token/s，Claude Code 的多步操作（读文件→思考→改代码→跑测试）每一步都是数秒级等待，大型重构任务可能分钟级；
3. **工具调用能力是门槛**：Claude Code 依赖模型稳定调用工具（读文件、编辑、执行命令）。工具调用不稳定的模型会导致"读不到文件、改错位置"，**务必先做工具调用实测**（用[第8章](../C8/1.%20轻量级%20Agent%20实现.md)的脚本）；
4. **思考型模型注意**：默认思考模式的模型（如 qwen3 思考变体）会先输出长推理链再行动，交互体感更慢，简单任务可关闭思考或选非思考模型；
5. **并发**：Claude Code 默认串行执行，本地模型并发瓶颈不明显，但多会话同时跑会排队（`OLLAMA_NUM_PARALLEL` 可调，见 [C2.5](../C2/5.%20GPU-CPU%20混合推理配置.md)）。

## 五、混合策略（推荐）

本地模型不是万能的，生产中最实用的模式是**混合策略**：

```
敏感/隐私任务(本地代码、机密数据) ──► 本地模型(qwen3 等)
复杂/大型任务(架构设计、大型重构)  ──► 云端模型(gemma4:cloud 等)
```

Ollama 的云端模型通道（`:cloud` 后缀）让两种模型在**同一套 launch 配置**下切换，只换 `--model` 参数即可。判断标准：

- 任务依赖**工具调用准确性** → 本地 8B 可能不够，切云端；
- 任务涉及**隐私数据** → 强制本地；
- 任务**耗时敏感** → 云端快得多。

## 六、配合 MCP 扩展工具

Claude Code 原生支持 MCP Server（见[第5章](../C5/4.%20常用%20MCP%20Server%20与%20Ollama%20配合.md)）：

```bash
claude mcp add weather -- python /path/to/mcp_weather_server.py
claude mcp list
```

**本地模型 + Claude Code + MCP 工具 = 完全本地化的编码 Agent**——模型、工具、数据全部不出机器。

## 本章小结

- 集成本质：Ollama 的 **Anthropic 兼容 API** 直接当 Claude Code 后端；
- 一键 `ollama launch claude`，手动配置就三个环境变量；
- 性能三要点：**64K+ 上下文、工具调用实测、接受分钟级大任务**；
- 混合策略：敏感用本地、复杂用云端，`--model` 一键切换。
