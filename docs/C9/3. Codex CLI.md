# 9.3 Codex CLI × Ollama 集成实战

> **版本基线**：Ollama 0.17.x + Codex CLI 0.153.x（**本章实测通过**：本书环境 Codex 0.153.4 + qwen3:8b-64k）
> **章节定位**：只讲「Ollama 怎么给 Codex CLI 当模型后端」，不讲 Codex 本身怎么用
> **官方文档**：[https://docs.ollama.com/integrations/codex](https://docs.ollama.com/integrations/codex)

## 一、集成原理

Codex CLI 支持 OpenAI 协议对接任意后端。Ollama 实现了 **OpenAI 兼容接口**（含 `/v1/responses`，本书实测 0.17.7 返回 200），因此 Codex 可以**零适配**使用本地模型：

```
Codex CLI ──OpenAI 协议(/v1/responses)──► Ollama(本地模型)
```

Codex 官方要求**较大的上下文窗口（≥64K tokens）**，本地模型选型时优先长上下文变体。

## 二、对接配置

### 方式一：一键（推荐）

```bash
# 安装 Codex CLI
npm install -g @openai/codex

# 一键对接(自动刷新模型目录 + 生成专用 profile)
ollama launch codex

# 只配置不启动
ollama launch codex --config
# 移除 Ollama 生成的 profile 与模型目录
ollama launch codex --restore
```

### 方式二：--oss 快速模式（手动）

```bash
codex --oss                       # 使用默认本地模型
codex --oss -m gpt-oss:120b       # 指定模型
codex --oss -m gpt-oss:120b-cloud # 云端模型
```

### 方式三：profile 持久配置（手动）

创建 `~/.codex/ollama-launch.config.toml`：

```toml
model = "qwen3:8b-64k"                        # 本地模型
model_provider = "ollama-launch"
model_catalog_json = "~/.codex/model.json"    # 模型目录(可选)

[model_providers.ollama-launch]
name = "Ollama"
base_url = "http://localhost:11434/v1/"       # 指向本地 Ollama
wire_api = "responses"                        # Responses API(Ollama 0.17.x 已支持)
```

启动：

```bash
codex --profile ollama-launch
```

> 非默认地址（如 WSL 访问 Windows 侧 Ollama）把 `base_url` 换成网关 IP 即可，见 [C2.5](../C2/2.%20Ollama%20在%20Windows%20下的安装与配置.md)。

## 三、本地实测（本书环境）

配置（profile 方式，`base_url` 指向 Windows 侧 Ollama 0.17.7，模型 `qwen3:8b-64k`）后执行：

```bash
codex exec --skip-git-repo-check "只回答一句话: 用本地模型跑通 Codex CLI 了吗?"
```

实测结果（真实输出节选）：

```
[模型进入思考过程…逐层分析任务、环境、上下文…]
codex
用本地模型跑通 Codex CLI 需要确保环境配置正确，您是否已安装依赖并配置好权限？
```

**验证结论**：

1. ✅ Codex CLI → Ollama → qwen3:8b-64k 链路完全打通（Responses API）；
2. ✅ 本地模型承担了 Codex 的完整推理职责（含思考链）；
3. ⚠️ 观察点：默认思考模式的 qwen3 变体输出冗长思考链，简单任务响应偏慢——**Codex 场景建议优先选非思考/快速变体，或关闭思考**，交互体感更好。

## 四、本地模型选型建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 通用编码 | 长上下文模型（≥64K），如 `qwen3:8b-64k` | Codex 官方要求 64K+ 上下文 |
| 快速交互 | 非思考变体（响应快、token 省） | 避免冗长推理链拖慢节奏 |
| 复杂任务 | `gpt-oss:120b`（本地/云端变体） | 大模型推理质量更高 |

## 五、性能边界提示

1. **64K 上下文是硬建议**：Codex 的会话模式（repository 扫描、多文件编辑）非常吃上下文，低于 64K 会频繁截断、丢失任务目标；
2. **思考链的代价**：qwen3 思考变体先"想"后做，输出 token 翻倍以上，在 Codex 的长任务中显著放大延迟——**简单任务关思考、复杂任务开思考**是实用策略；
3. **工具调用**：Codex 重度依赖工具调用（读文件、编辑、执行命令），务必先用[第8章](../C8/1.%20轻量级%20Agent%20实现.md)脚本实测模型的工具调用稳定性；
4. **Web 搜索**：Codex 的 web-search 请求经 Ollama profile 转发（本地与云端模型均可），需 `ollama signin`；不需要时关闭：
   ```bash
   codex --profile ollama-launch -c 'web_search="disabled"'
   ```

## 六、混合策略：本地/云端 profile 切换

Codex 的 profile 机制天然支持混合策略：

```toml
# ~/.codex/ollama-launch.config.toml 里直接换 model 字段
model = "qwen3:8b-64k"        # 敏感任务: 本地
# model = "gpt-oss:120b-cloud" # 复杂任务: 云端(切换时取消注释)
```

敏感代码走本地 profile，大型重构切云端模型，**同一套 Codex 配置，只改一行 model**。

## 本章小结

- 一键 `ollama launch codex`；手动三条路：`--oss` 快速模式、profile 持久配置；
- **实测验证**：Codex 0.153.4 + qwen3:8b-64k 全链路跑通（Responses API）；
- 关键边界：**64K+ 上下文、思考链延迟、工具调用稳定性**；
- 混合策略：一行 model 切换本地/云端。
