# 9.2 DeepSeek Harness × Ollama 集成实战

> **版本基线**：Ollama 0.17.x + DeepSeek Harness（`@deepseek-ai/dsh`）
> **章节定位**：只讲「Ollama 怎么给 DeepSeek Harness 当模型后端」，不讲 Harness 本身怎么用
> **官方文档**：[https://docs.ollama.com/integrations/deepseek-harness](https://docs.ollama.com/integrations/deepseek-harness)
> **仓库**：[https://github.com/deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)

## 一、集成原理

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（CLI 名 `dsh`）是 DeepSeek 开源的 Agent 框架，核心理念是 **"Everything is a Plugin"**——模型、工具、技能全部以插件形式接入。Ollama 为它提供**模型 provider 插件**，使本地模型成为 Harness 的推理后端。

> ⚠️ 官方提示：DeepSeek Harness 目前是 **developer preview（开发者预览版）**，上游配置可能随版本变化，以官方文档与 `dsh --help` 为准。

## 二、对接配置

### 方式一：一键（推荐）

```bash
ollama launch dsh
```

Ollama 自动安装 `@deepseek-ai/dsh`（npm 包，需 Node.js）并完成配置。指定模型：

```bash
# 本地模型
ollama launch dsh --model qwen3.8
# 云端模型(需 ollama signin)
ollama launch dsh --model deepseek-v4-flash:cloud
```

只配置不启动：

```bash
ollama launch dsh --config
```

### 方式二：手动安装

```bash
# 依赖 Node.js
npm install -g @deepseek-ai/dsh@latest
# 然后同样用 ollama launch dsh 完成对接
```

### 传递额外参数

`ollama launch dsh` 不接受额外的 `--patch` 参数，其他 Harness 参数放在 `--` 之后：

```bash
ollama launch dsh -- --port 3081
```

## 三、配置存储与隔离

这是 DeepSeek Harness 集成的关键设计——**配置不互相污染**：

| 配置文件 | 内容 | 谁管理 |
|---|---|---|
| `~/.ollama/launch/dsh/settings.yaml` | Ollama 写入的模型/provider/联网配置 | Ollama（后加载，优先级高） |
| `~/.dsh/settings.yaml` | 用户自己的 Harness 配置 | 用户（Ollama 不触碰） |
| profiles / sessions / credentials | 用户数据 | 用户（Ollama 不触碰） |

这意味着：`ollama launch dsh` 只注入模型后端相关配置，你的 Harness 习惯配置（profile、会话、凭据）完全保留。

## 四、本地模型选型建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 通用编码 Agent | `qwen3.8`（8B） | 工具调用稳定、资源友好 |
| 复杂推理/规划 | DeepSeek-R1 蒸馏版 | 推理型模型适合长链路任务 |
| 深度编码（大仓库） | 云端 `deepseek-v4-flash:cloud` | 本地 8B 在超大仓库力不从心 |

## 五、性能边界提示

1. **Web 搜索默认开启**：DeepSeek Harness 的联网搜索自动启用，但要求模型**支持工具调用**且需 Ollama 云访问（`ollama signin`）。纯离线环境注意：网络功能不可用，但本地工具不受影响；
2. **上下文与插件**：Harness 的插件系统会把工具/技能描述注入上下文，模型上下文越大，能挂的插件越多——本地模型建议 64K 上下文，插件数量克制（参照[第5章](../C5/4.%20常用%20MCP%20Server%20与%20Ollama%20配合.md)的工具数量原则）；
3. **预览版变更**：`dsh` 的配置格式在预览期可能调整，升级后如对接失效，先看 `~/.ollama/launch/dsh/settings.yaml` 是否被正确写入，再检查官方 changelog（[living-docs/changelog.md](../../living-docs/changelog.md) 会同步记录）；
4. **Node.js 依赖**：`dsh` 是 npm 包，Windows 上需先安装 Node.js for Windows。

## 六、混合策略

```bash
# 敏感任务: 本地模型
ollama launch dsh --model qwen3.8
# 复杂任务: 云端模型
ollama launch dsh --model deepseek-v4-flash:cloud
```

两条命令切换模型后端，profile/会话数据不变。**判断标准同 9.1**：隐私 > 本地，复杂度/速度 > 云端。

## 本章小结

- `ollama launch dsh` 一键把 DeepSeek Harness 接上本地模型；
- 配置隔离设计优秀：Ollama 只管模型后端，用户配置不受影响；
- 注意：预览版特性、Web 搜索需 Ollama 云访问、Node.js 依赖；
- 混合策略：敏感用本地（qwen3.8），复杂用云端（deepseek-v4-flash:cloud）。
