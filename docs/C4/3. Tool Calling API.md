# Ollama Tool Calling API

> **版本基线**：Ollama 0.17.x（本文所有示例均在本机 Ollama 0.17.7 + qwen3:8b-64k 实测通过）
> **章节定位**：详解工具调用的请求/响应结构——这是 Agent 循环的第一性原理（配合[第7章](../C7)原理讲解）

## 一、Tool Calling 是什么

Tool Calling（工具调用，也叫 Function Calling）让模型在对话中**输出结构化的"调用某个工具的请求"**，而不是直接回答。典型流程：

```
用户提问 → 模型分析"需要外部信息" → 输出工具调用请求(JSON)
        → 程序执行工具(查天气/查数据库/跑代码) → 把结果回传给模型
        → 模型基于结果生成最终回答
```

这构成了 Agent 的核心循环（ReAct 的 Act 环节）。本地模型能不能稳定输出正确的工具调用，直接决定它能否成为 Agent 后端——这就是本教程反复强调 Tool Calling 的原因。

## 二、请求结构：如何声明工具

在 `/api/chat` 请求中携带 `tools` 数组（OpenAI 兼容接口用法一致）：

```bash
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3:8b",
  "messages": [{"role": "user", "content": "北京和上海今天谁更热?"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询指定城市当天的温度",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type": "string", "description": "城市名"}
        },
        "required": ["city"]
      }
    }
  }],
  "stream": false
}'
```

**关键点**：

- `tools` 是数组，一次可声明多个工具，模型会自行选择；
- 每个工具用 **JSON Schema** 描述参数（`type/properties/required`），模型据此生成合法参数；
- `description` 写得越清楚，模型选对工具、填对参数的概率越高——**工具描述就是给模型看的文档**。

## 三、响应结构：模型如何请求调用

### 3.1 原生 API（/api/chat）响应

实测返回：

```json
{
  "message": {
    "role": "assistant",
    "content": "",
    "tool_calls": [{
      "id": "call_cgbvilmb",
      "function": {
        "name": "get_weather",
        "arguments": {"city": "北京"}
      }
    }]
  },
  "done": true
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `message.tool_calls[].id` | 工具调用 ID，**回传结果时必须带上** |
| `message.tool_calls[].function.name` | 要调用的工具名 |
| `message.tool_calls[].function.arguments` | 参数对象（原生 API 已解析为对象） |

### 3.2 OpenAI 兼容接口（/v1/chat/completions）响应

实测返回（注意与原生 API 的差异——**arguments 是 JSON 字符串**，且支持并行调用）：

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_nyp9i40d",
          "type": "function",
          "function": {"name": "get_weather", "arguments": "{\"city\":\"北京\"}"}
        },
        {
          "id": "call_6eyqeaxt",
          "type": "function",
          "function": {"name": "get_weather", "arguments": "{\"city\":\"上海\"}"}
        }
      ]
    },
    "finish_reason": "tool_calls"
  }]
}
```

**要点**：

- `arguments` 是 **JSON 字符串**，使用前需要 `JSON.parse`；
- `finish_reason` 为 `tool_calls` 表示"模型请求调用工具"（区别于正常结束的 `stop`）；
- 上例展示了**并行工具调用**：一次返回两个 get_weather 调用，程序可以并发执行。

## 四、完整循环：执行工具 → 回传结果 → 最终回答

工具执行后，把结果作为 `role: "tool"` 的消息回传（必须带 `tool_call_id`），模型才能"看到"结果并继续：

```bash
curl http://localhost:11434/v1/chat/completions -d '{
  "model": "qwen3:8b-64k",
  "messages": [
    {"role": "user", "content": "北京和上海今天谁更热?"},
    {"role": "assistant", "content": null, "tool_calls": [
      {"id": "call_nyp9i40d", "type": "function", "function": {"name": "get_weather", "arguments": "{\"city\":\"北京\"}"}},
      {"id": "call_6eyqeaxt", "type": "function", "function": {"name": "get_weather", "arguments": "{\"city\":\"上海\"}"}}
    ]},
    {"role": "tool", "tool_call_id": "call_nyp9i40d", "content": "北京 32°C"},
    {"role": "tool", "tool_call_id": "call_6eyqeaxt", "content": "上海 35°C"}
  ],
  "tools": [/* 与第一轮相同的 tools 数组 */],
  "stream": false
}'
```

实测最终回答：

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "上海今天更热，气温为35°C，而北京气温为32°C。"
    },
    "finish_reason": "stop"
  }]
}
```

**循环要点**：

- assistant 的 tool_calls 消息必须**原样回传**（content 为 null）；
- 每个工具结果用独立的 `tool` 消息回传，`tool_call_id` 一一对应；
- 回传后模型在下一轮要么调用更多工具、要么给出最终回答（`finish_reason: stop`）。

## 五、常见坑与调试

| 现象 | 原因 | 处理 |
|---|---|---|
| 模型不调用工具 | 工具描述不清 / 模型不支持 | 检查模型家族是否支持工具调用；把 description 写具体 |
| 参数格式错误（JSON 解析失败） | 小模型量化损失 | 用更大的模型或更高精度量化（见[第3章](../C3)）；给参数的 description 更明确 |
| arguments 解析报错（OpenAI 接口） | arguments 是字符串不是对象 | 先 `JSON.parse`；解析失败时做容错（提示模型重新生成） |
| 一轮调用多个工具 | 模型并行调用（正常行为） | 程序并发执行所有调用，逐个回传结果 |
| 工具结果太长 | 上下文膨胀 | 截断工具输出（如只保留前 2000 字符）；控制 num_ctx |

## 六、结构化输出（format: json）与 Tool Calling 的关系

两者容易混淆：

- `format: "json"` 是**强制输出为 JSON**（适合"给我一份 JSON 报告"）；
- Tool Calling 是**输出结构化的工具调用请求**（适合"去查数据再回答"）。

Tool Calling 是 Agent 场景的主角；`format: json` 适合单轮结构化抽取。两者可以组合使用（工具参数本身就是 JSON Schema 约束的结构化输出）。

## 本章小结

- Tool Calling = 模型输出结构化工具调用请求，是 Agent 循环的第一性原理；
- 原生 API：`arguments` 是对象；OpenAI 兼容接口：`arguments` 是 JSON 字符串、`finish_reason=tool_calls`；
- **完整循环四步**：声明工具 → 模型请求调用 → 执行工具 → 回传结果 → 最终回答；
- 本地模型工具调用"可用但需容错"，参数解析失败要设计重试。
