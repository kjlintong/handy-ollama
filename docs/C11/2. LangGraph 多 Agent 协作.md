# 本地多 Agent 协作：LangGraph + Ollama

> **版本基线**：Ollama 0.17.x + LangGraph（本章示例**实测通过**：本书环境 qwen3:8b-64k）
> **章节定位**：用 LangGraph 的图编排能力构建可控的多 Agent 工作流——比 CrewAI 更精细，适合需要自定义流程的场景
> **代码**：`notebook/C11/langgraph_agent_test.py`（实测脚本）

## 一、LangGraph 与 CrewAI 的区别

| 维度 | CrewAI | LangGraph |
|---|---|---|
| 编排模型 | 角色/任务声明式 | **有向图**（节点 + 边 + 状态） |
| 灵活度 | 高（开箱即用） | 极高（任意流程） |
| 控制粒度 | 粗（顺序/层级） | 细（条件分支、循环、并行） |
| 学习成本 | 低 | 中 |
| 适合 | 标准协作流水线 | 自定义复杂工作流 |

**一句话**：CrewAI 是"配置团队"，LangGraph 是"画流程图"。

## 二、LangGraph 核心概念

```
┌────────────────────────────────────────────┐
│ State(状态): 整个流程共享的数据(如消息列表)     │
└────────────────────────────────────────────┘
        │
   ┌────▼────┐    ┌─────────┐    ┌─────────┐
   │ Node A  ├───►│ Node B  ├───►│ Node C  │
   │ (Agent) │    │ (工具)   │    │ (Agent) │
   └─────────┘    └─────────┘    └─────────┘
        │                ▲
        └─── 条件边(循环) ─┘
```

- **Node（节点）**：一个处理步骤（模型调用、工具执行、数据处理）；
- **Edge（边）**：节点间流转，支持条件分支；
- **State（状态）**：贯穿全流程的共享数据。

## 三、最快上手：预构建 Agent（实测）

LangGraph 提供预构建的 ReAct Agent，接上本地模型即可用（`create_react_agent` 在 LangGraph 1.0 后迁移至 `langchain.agents.create_agent`）：

```python
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent

# 本地模型(OpenAI 兼容接口, 与第6章实测写法一致)
model = ChatOpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",
    model="qwen3:8b",
    temperature=0.2,
)

def get_weather(city: str) -> str:
    """查询指定城市今天的天气。city: 城市名"""
    data = {"北京": "晴, 32°C", "上海": "多云转阵雨, 35°C"}
    return f"{city}: {data.get(city, '暂无数据')}"

agent = create_agent(model, tools=[get_weather])

result = agent.invoke({"messages": [("user", "北京今天天气怎么样?")]})
for msg in result["messages"]:
    print(f"[{msg.type}] {msg.content[:80]}")
```

实测输出（本书环境：Ollama 0.17.7 + qwen3:8b-64k，真实结果）：

```
[human] 北京今天天气怎么样?
[ai]
[tool] 北京: 晴, 32°C
[ai] 北京今天天气晴朗，气温32摄氏度。
```

模型自主完成了"调用天气工具 → 基于结果回答"的完整 ReAct 循环。

## 四、自定义图：研究 → 写作 双 Agent 流水线

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    topic: str
    research: str
    final: str

def research_node(state: State):
    """研究员 Agent: 基于 topic 生成要点"""
    resp = model.invoke(f"调研主题「{state['topic']}」, 输出 3 个要点, 每点一句话")
    return {"research": resp.content}

def write_node(state: State):
    """写作员 Agent: 基于调研要点写概述"""
    resp = model.invoke(f"基于以下要点写 100 字概述:\n{state['research']}")
    return {"final": resp.content}

# 构图: 研究 → 写作 → 结束
graph = StateGraph(State)
graph.add_node("research", research_node)
graph.add_node("write", write_node)
graph.add_edge(START, "research")
graph.add_edge("research", "write")
graph.add_edge("write", END)

app = graph.compile()
out = app.invoke({"topic": "本地大模型部署"})
print(out["final"])
```

要点：

- **State 定义数据流**：`topic → research → final` 逐节点填充；
- **节点就是普通函数**：内部可以是模型调用、工具调用、任意逻辑；
- **边控制流转**：加条件边可实现"研究结果不达标 → 重做"这类循环。

## 五、本地模型 + LangGraph 的实践建议

1. **先用预构建 Agent 跑通**（第三节），再上自定义图——先验证模型能力，再谈编排；
2. **节点输出要短**：State 里的中间结果会进入下游节点上下文，输出越长越吃上下文；
3. **循环要设上限**：条件边加 `recursion_limit`，防止本地模型"绕圈"；
4. **并行节点注意显存**：并行分支 = 多模型同时驻留，先看[3. 本地模型资源调度](./3.%20本地模型资源调度.md)。

## 本章小结

- LangGraph 用 **State/Node/Edge** 图模型编排 Agent，控制粒度最细；
- 预构建 Agent（`create_agent`）+ OpenAI 兼容接口 = 最速集成，本章实测通过；
- 自定义图：State 定数据流、Node 写逻辑、Edge 控流转；
- 本地实践三原则：先验证模型、节点输出短、循环设上限。
