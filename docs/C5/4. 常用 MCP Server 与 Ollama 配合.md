# 常用 MCP Server 与 Ollama 配合

> **版本基线**：2026 年 9 月，MCP 生态快速发展，具体 Server 以官方仓库为准
> **章节定位**：学会接入现成的 MCP Server，让本地模型获得文件、网页、代码、搜索等真实能力；并了解接入 Harness 的标准姿势

## 一、现成的 MCP Server（拿来即用）

不必所有工具都自己写。官方与社区有大量高质量 MCP Server，通过 `npx` 一条命令即可启动：

| Server | 能力 | 启动方式（stdio） |
|---|---|---|
| **filesystem**（官方） | 读写本地文件/目录 | `npx -y @modelcontextprotocol/server-filesystem <允许的路径>` |
| **fetch**（官方） | 抓取网页内容 | `npx -y @modelcontextprotocol/server-fetch` |
| **github**（官方） | GitHub 仓库/Issue/PR 操作 | `npx -y @modelcontextprotocol/server-github` |
| **memory**（官方） | 知识图谱记忆（跨会话） | `npx -y @modelcontextprotocol/server-memory` |
| **sequential-thinking** | 引导模型逐步推理 | `npx -y @modelcontextprotocol/server-sequential-thinking` |
| **playwright / puppeteer** | 浏览器自动化 | `npx -y @playwright/mcp` |
| **sqlite / postgres** | 数据库查询 | `npx -y @modelcontextprotocol/server-sqlite <db路径>` |

> 完整目录见 [https://github.com/modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers)（官方）与 [https://mcp.so](https://mcp.so)（社区聚合）。

## 二、接入方式一：手写 Client（第3节模式）

上一节的 `ollama_mcp_agent.py` 可以**零修改**接任意 stdio Server，只需换 `args`：

```python
# 例如换成官方 filesystem server
server_params = StdioServerParameters(
    command="npx",
    args=["-y", "@modelcontextprotocol/server-filesystem", "/home/ryan/docs"],
)
```

工具发现、schema 转换、结果回传的胶水代码完全复用。**这就是协议的意义：换工具，不换代码。**

> ⚠️ 注意：`npx` 首次运行会联网下载 Server 包，且 tools 数量会变多（如 filesystem 有十几个工具），对本地小模型的"工具选择能力"是考验，见下文第四节。

## 三、接入方式二：在 Harness 里配置（Claude Code 示例）

主流 Harness 都内置 MCP Client，配置后 Agent 自动获得工具（不需要自己写胶水代码）。

**Claude Code 添加 MCP Server：**

```bash
# 全局(所有项目可用)
claude mcp add weather -- python /path/to/mcp_weather_server.py

# 项目级
claude mcp add --scope project weather -- python /path/to/mcp_weather_server.py

# 查看/删除
claude mcp list
claude mcp remove weather
```

配置后，Claude Code 会话中可以直接说"查一下北京天气"，它会自动调用 weather server 的工具。**如果 Claude Code 配的是 Ollama 本地模型后端（见[第9章](../C9/1.%20Claude%20Code.md)），那么这条链就是：本地模型 + MCP 工具 = 本地 Agent。**

**Codex CLI：**

```bash
codex mcp add weather -- python /path/to/mcp_weather_server.py
```

**DeepSeek Harness 与其他工具**的 MCP 配置方式类似（都在各自的 settings/配置文件中声明 server 列表），配置项本质相同：`名称 + 启动命令 + 参数`。

## 四、本地模型 + MCP 的工程要点

本地模型（尤其 8B 级别）接 MCP 工具时，有几个与云端模型不同的注意点：

### 4.1 控制工具数量

- 模型每轮都要"看完所有工具描述再选"，**工具越多，选择越容易出错**（选错、参数填错）；
- 经验值：8B 模型单次会话的工具数量 **≤ 8 个**效果最佳；超过 15 个明显退化；
- 对策：为不同任务准备不同的 Server（查天气的、管文件的、搜网页的），按需挂载，而不是全挂上。

### 4.2 精简工具描述

- 工具描述是模型的"说明书"，本地小模型对长描述的遵循能力弱；
- 对策：描述用**一句话讲清用途 + 参数含义**，避免大段 Markdown 格式说明；
- 用 `sequential-thinking` 这类"思维工具"时注意：它会把推理链变成工具调用，本地模型输出会明显变慢，按需使用。

### 4.3 容错设计

- 本地模型偶发参数格式错误是常态（见[第4章](../C4/3.%20Tool%20Calling%20API.md)），生产代码要有"重试 + 错误回传"；
- 工具返回内容过长会快速撑爆上下文：对工具输出做截断（如 2000 字符）。

### 4.4 安全边界

- filesystem / github / sqlite 这类**高权限工具**，务必限制可访问路径/仓库，并用只读模式起步；
- 本地模型没有云端审查，**工具权限即安全边界**，最小授权原则。

## 本章小结

- 官方 + 社区 MCP Server 覆盖文件、网页、GitHub、数据库、浏览器等常见能力，npx 一条命令即用；
- 接入两条路：手写 Client（薄胶水复用）或 Harness 内配置（零代码）；
- 本地模型 + MCP 的工程三原则：**工具少而精、描述短而清、执行有容错**；
- 安全边界：高权限工具最小授权。
