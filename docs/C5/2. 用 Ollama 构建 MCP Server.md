> **版本基线**：mcp Python SDK 2.x（实测通过）
> **章节定位**：动手写一个 MCP Server，理解工具如何通过标准协议暴露给任何 Agent
> **代码**：`notebook/C5/mcp_weather_server.py`（本文示例即该文件）

## 一、为什么先写 Server

MCP Server 是"工具的生产者"。先掌握 Server，你就拥有了**把任意能力（查天气、读文件、连数据库、跑代码）标准化暴露给所有 Agent** 的能力。写完一个 Server，Claude Code、Codex、DeepSeek Harness 以及我们自己写的 Agent 都能直接用——这就是协议的价值。

## 三、最小 MCP Server（30 行）

```python
from mcp.server.mcpserver import MCPServer

# 创建 Server 实例: 服务名 + 描述 + 版本
server = MCPServer(
    "weather",
    title="天气查询服务",
    description="提供城市天气查询与预报的 MCP 服务(教学示例)",
    version="1.0.0",
)

@server.tool()
def get_weather(city: str) -> str:
    """查询指定城市今天的天气情况, 返回温度与天气描述。

    Args:
        city: 城市名, 例如 "北京"、"上海"。
    """
    data = {"北京": "晴, 32°C", "上海": "多云转阵雨, 35°C"}
    return f"{city}: {data.get(city, '暂无数据')}"

if __name__ == "__main__":
    server.run()  # 默认 stdio 传输
```

要点：

1. `MCPServer(...)` 声明服务元信息；
2. `@server.tool()` 注册工具——**函数的 docstring 就是工具描述**，会被协议原样传给模型，所以要写清楚参数含义；
3. `server.run()` 默认走 **stdio 传输**，等待 Client 以子进程方式连接；
4. 参数类型注解（`city: str`）自动生成 JSON Schema。

## 四、完整示例：天气服务（两个工具）

`notebook/C5/mcp_weather_server.py` 提供了完整版：`get_weather`（今日天气）与 `get_forecast`（未来预报），含模拟数据与参数校验。核心结构：

```python
from mcp.server.mcpserver import MCPServer

server = MCPServer("weather", title="天气查询服务", version="1.0.0")

@server.tool()
def get_weather(city: str) -> str:
    """查询指定城市今天的天气情况。..."""
    ...

@server.tool()
def get_forecast(city: str, days: int = 3) -> str:
    """查询指定城市未来几天的天气预报。..."""
    ...

if __name__ == "__main__":
    server.run()
```

运行：

```bash
python mcp_weather_server.py
```

程序会**等待 stdin 上的协议消息**（不会打印任何东西）。它由 MCP Client 以子进程方式启动，不需要手动交互。

## 五、如何验证 Server 可用

不写 Client 也能快速验证——用 `mcp` 包自带的调试工具：

```bash
# 方式一: MCP Inspector(图形化调试台)
npx @modelcontextprotocol/inspector python mcp_weather_server.py

# 方式二: 命令行直接列出工具
npx -y @modelcontextprotocol/cli tools --transport stdio -- python mcp_weather_server.py
```

输出应包含：

```
get_weather   查询指定城市今天的天气情况...
get_forecast  查询指定城市未来几天的天气预报...
```

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| Client 报 "No module named 'mcp'" | Client 用系统 python 启动 Server | Client 端用 `sys.executable` 启动（见 [3. MCP Client 调用链](./3.%20MCP%20Client%20调用链.md)） |
| 工具列表为空 | 装饰器没生效 | 确认 `@server.tool()` 修饰的是**顶层函数**，且函数有 docstring |
| 工具描述出现 "Args:" 等冗余 | pydantic 把 docstring 完整传给了描述 | 教学无碍；生产可精简 docstring 格式 |
| 想暴露文件/数据库等资源 | 超出 Tools 范围 | 用 Resources 或直接写专用 Server（参考官方 examples） |

## 本章小结

- 一个 MCP Server = `MCPServer` 实例 + 若干个 `@server.tool()` 函数 + `run()`；
- 函数 docstring 即工具描述，是模型选择工具的"说明书"；
- stdio 传输让 Server 以子进程方式被任意 Client 拉起；
- 用 `@modelcontextprotocol/cli` 可零代码验证 Server。
