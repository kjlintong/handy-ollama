# MCP 协议架构

> **版本基线**：MCP 协议（Model Context Protocol），写作时 SDK 版本 mcp 2.x
> **章节定位**：理解 MCP 是什么、为什么成为 Agent 工具调用的事实标准、它的架构长什么样。**本章只讲协议本身，不绑定任何特定工具。**

## 一、MCP 是什么

MCP（Model Context Protocol，模型上下文协议）是由 Anthropic 于 2024 年底提出的**开放协议**，解决一个根本问题：

> **每个 Agent 工具都要为每个外部系统写一套集成代码，N×M 的适配地狱。**

- 没有 MCP：Claude Code 要写代码解释器插件、GitHub 插件、数据库插件……每个工具厂商也要为每个 Agent 写 SDK；
- 有了 MCP：**一套协议，两端实现**。Agent（MCP Client）通过标准协议发现并调用工具，外部系统（MCP Server）通过标准协议暴露工具。任何 Client 接任何 Server，即插即用。

MCP 因此迅速成为 Agent 工具调用的**事实标准**：Claude Code、Codex CLI、DeepSeek Harness、OpenCode、Cursor 等主流 Agent 工具全部原生支持 MCP；文件系统、GitHub、数据库、浏览器等官方与社区 MCP Server 数以千计。

## 二、协议架构

MCP 采用 **客户端-服务器（Client-Server）** 架构，核心元素：

```
┌─────────────────────┐        MCP 协议         ┌─────────────────────┐
│    MCP Client       │ ◄──────────────────────► │     MCP Server      │
│  (Claude Code /     │      (JSON-RPC 2.0)      │  (天气服务 / 文件系统 │
│   Codex / 我们的     │                          │   / GitHub / 数据库…) │
│   ollama_mcp_agent) │                          │                     │
└─────────────────────┘                          └─────────────────────┘
```

### 2.1 三个核心能力

| 能力 | 作用 | 类比 |
|---|---|---|
| **Tools（工具）** | Server 暴露可执行的函数（查天气、读写文件、搜网页） | API 端点 |
| **Resources（资源）** | Server 暴露可读取的数据（配置文件、文档内容） | REST 资源 |
| **Prompts（提示词模板）** | Server 暴露可复用的提示词模板 | 快捷指令 |

Agent 场景的主角是 **Tools**——本教程聚焦这一项。

### 2.2 传输方式

| 传输 | 说明 | 适用 |
|---|---|---|
| **stdio** | 通过标准输入输出通信，Client 以子进程方式启动 Server | 本地工具，最常用 |
| **Streamable HTTP** | 通过 HTTP 通信，Server 是常驻服务 | 远程/共享服务 |

### 2.3 协议消息

MCP 基于 JSON-RPC 2.0。一次工具调用链路上有四个关键方法：

```
initialize            # 握手: 协商协议版本与能力
tools/list            # Client 发现 Server 有哪些工具
tools/call            # Client 调用某个工具
notifications/*       # 通知(如日志、进度)
```

## 三、一次完整的 MCP 工具调用

以「本地模型通过 MCP 查询天气」为例（完整可运行代码见 [3. MCP Client 调用链](./3.%20MCP%20Client%20调用链.md)）：

```
1. Client 启动 Server 子进程 (stdio)
2. initialize 握手
3. tools/list        → 得到 get_weather / get_forecast 的 JSON Schema
4. Client 把工具 schema 转成 Ollama 的 tools 参数
5. 模型返回 tool_calls: get_weather(city="北京")
6. tools/call        → Server 执行, 返回 "北京: 晴, 32°C"
7. 结果回传给模型    → 模型生成最终回答
```

**注意第 4 步的关键设计**：Ollama 本身不是 MCP Client，但它支持 OpenAI function calling 格式的工具参数——MCP 工具的 JSON Schema 可以直接映射过去。**MCP 管"工具的发现与执行"，Ollama 管"模型的推理与决策"，中间由一段薄胶水代码连接。**

## 四、为什么说 MCP 是"协议层"基础设施

回看本教程的定位——"Agent 时代的本地模型底座"：

- **MCP 让工具与模型解耦**：工具生态（MCP Server）与模型生态（Ollama）各自演进，通过标准协议组合；
- **本地模型 + MCP = 完整的本地 Agent 能力**：不依赖任何云端 API，模型、工具、数据全部本地；
- **一次编写，处处可用**：写一个 MCP Server，Claude Code、Codex、我们的手写 Agent 都能用，不需要为每个客户端适配。

这正是本教程第 5 章放在"协议与接口层"的原因：**MCP 是连接"本地模型"与"Agent 世界"的标准插座。**

## 五、MCP 与 Tool Calling API 的关系

| 概念 | 角色 | 位置 |
|---|---|---|
| **Tool Calling API**（[第4章](../C4/3.%20Tool%20Calling%20API.md)） | 模型输出结构化工具调用请求的能力 | 模型 API 层 |
| **MCP** | 工具的标准发现与执行协议 | 工具生态层 |

Tool Calling 解决"模型怎么表达调用意图"，MCP 解决"工具怎么被找到、怎么被执行"。两者互补：**模型通过 Tool Calling 决定调用谁，程序通过 MCP 找到并执行它。**

## 本章小结

- MCP 是 Agent 工具调用的**事实标准协议**（JSON-RPC 2.0，Client-Server）；
- 三大能力：Tools / Resources / Prompts，Agent 场景核心是 Tools；
- 传输方式：stdio（本地子进程）与 Streamable HTTP（远程服务）；
- 调用链：握手 → 发现工具 → 模型决策 → 执行工具 → 回传结果；
- MCP（工具层）与 Tool Calling API（模型层）互补，共同构成 Agent 的工具能力。
