# MCP Client 调用链：让 Ollama 模型使用 MCP 工具

> **版本基线**：mcp Python SDK 2.x + ollama-python 0.6.x（本章全部示例在本机实测通过）
> **章节定位**：本章是第 5 章的核心——打通「本地模型 ↔ MCP 工具」的完整调用链
> **代码**：`notebook/C5/mcp_client.py`、`notebook/C5/ollama_mcp_agent.py`

## 一、调用链全景

```
┌─────────────────────────────────────────────────────────────┐
│                     我们的 Agent 程序                         │
│  ┌──────────────┐    ┌──────────────┐    ┌───────────────┐  │
│  │ MCP Client   │    │  Ollama API  │    │  MCP Server   │  │
│  │ (发现/执行工具)│    │ (模型推理决策) │    │ (天气工具)     │  │
│  └──────┬───────┘    └──────┬───────┘    └──────┬────────┘  │
└─────────┼───────────────────┼───────────────────┼───────────┘
          │ 1. tools/list     │                   │
          ├──────────────────►│                   │
          │ 2. 工具 schema 转换  │                   │
          │ 3. chat(tools=…)   │                   │
          │◄───────────────────┤                   │
          │ 4. tool_calls 返回  │                   │
          │ 5. tools/call      │                   │
          │───────────────────────────────────────►│
          │ 6. 工具结果        │                   │
          │◄───────────────────────────────────────┤
          │ 7. 结果回传 chat   │                   │
          │◄───────────────────┤                   │
          │ 8. 最终回答        │                   │
```

**关键设计**：MCP 只负责工具的**发现与执行**，模型决策完全交给 Ollama。两者通过"JSON Schema 转换 + 消息回传"对接，这就是全书的薄胶水模式。

## 二、第一步：纯 MCP Client（发现 + 调用工具）

`notebook/C5/mcp_client.py` 演示最基础的 Client 能力：

```python
import asyncio
import sys
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

server_params = StdioServerParameters(
    command=sys.executable,   # 用当前解释器启动 server, 保证同一个 venv
    args=["mcp_weather_server.py"],
)

async def main() -> None:
    # stdio_client: 启动子进程并建立双向管道
    async with stdio_client(server_params) as (read, write):
        # ClientSession: 封装 MCP 协议层
        async with ClientSession(read, write) as session:
            await session.initialize()          # 1. 握手

            tools = await session.list_tools()  # 2. 发现工具
            for tool in tools.tools:
                print(f"  - {tool.name}: {tool.description}")

            # 3. 调用工具
            result = await session.call_tool("get_weather", {"city": "北京"})
            for content in result.content:
                print("结果:", content.text)

asyncio.run(main())
```

实测输出：

```
MCP Server 暴露的工具:
  - get_weather: 查询指定城市今天的天气情况...
  - get_forecast: 查询指定城市未来几天的天气预报...
调用 get_weather(city='北京') ...
结果: 北京: 晴, 32°C, 微风
```

**四个关键调用**：`initialize()`（握手）→ `list_tools()`（发现）→ `call_tool()`（执行）→ `result.content`（取结果）。这就是 MCP 客户端的全部骨架。

## 三、第二步：桥接 Ollama（核心）

`notebook/C5/ollama_mcp_agent.py` 把 MCP 工具接给本地模型。两个关键转换：

### 3.1 工具 schema 转换（MCP → Ollama）

```python
def to_ollama_tools(mcp_tools: list) -> list:
    tools = []
    for tool in mcp_tools:
        tools.append({
            "type": "function",
            "function": {
                "name": tool.name,
                "description": tool.description or "",
                "parameters": tool.input_schema,  # MCP 的 JSON Schema 可直接复用
            },
        })
    return tools
```

MCP 工具的 `input_schema` 本身就是 JSON Schema，与 Ollama 的 tools 参数格式**天然兼容**，只差一层包装。

### 3.2 Agent 循环（模型决策 → 执行 → 回传）

```python
for round_no in range(1, MAX_ROUNDS + 1):
    # 调用本地模型, 携带工具清单
    response = client.chat(model=OLLAMA_MODEL, messages=messages, tools=tools)
    msg = response.message

    if msg.tool_calls:                    # 模型要调用工具
        messages.append({"role": "assistant", "content": msg.content or "",
                         "tool_calls": msg.tool_calls})
        for call in msg.tool_calls:
            fn = call.function
            # 通过 MCP 执行工具
            result = await session.call_tool(fn.name, fn.arguments or {})
            text = "".join(c.text for c in result.content if hasattr(c, "text"))
            # 结果回传 (role="tool")
            messages.append({"role": "tool", "content": text})
    else:                                 # 模型给出最终回答
        print(f"[模型] 最终回答: {msg.content}")
        return
```

要点：

- **assistant 消息原样回传**（含 `tool_calls`），否则模型不知道"这是它刚才的调用"；
- **工具结果用 `role="tool"`** 回传，这是 ollama-python 约定的格式；
- `MAX_ROUNDS` 上限防止模型陷入无限调用循环。

## 四、实测运行（本书环境：Ollama 0.17.7 + qwen3:8b-64k）

```bash
# 本地默认 Ollama
python ollama_mcp_agent.py

# 非默认地址(如 WSL 访问 Windows 侧 Ollama, 见 C2.5)
OLLAMA_HOST=http://172.28.176.1:11434 OLLAMA_MODEL=qwen3:8b-64k python ollama_mcp_agent.py
```

实测输出（真实结果）：

```
[MCP] 发现 2 个工具: ['get_weather', 'get_forecast']

===== 第 1 轮 =====
[模型] 调用工具: get_weather({"city": "北京"})
[工具] 返回: 北京: 晴, 32°C, 微风
[模型] 调用工具: get_forecast({"city": "北京", "days": 3})
[工具] 返回: 北京 未来 3 天预报: 第1天: 晴 32°C; ...

===== 第 2 轮 =====
[模型] 最终回答: 北京今天天气晴，温度32°C，微风。未来三天预报如下：...
```

观察点：

1. 模型**自动拆解任务**：先查今日天气，再查未来三天预报——两步工具调用，一步一轮；
2. 参数完全正确：`{"city": "北京", "days": 3}` 与工具 schema 一致；
3. 第二轮回传结果后，模型**基于真实工具数据**生成最终回答，全程无幻觉；
4. 整个过程**零云端依赖**：模型在本地、工具在本地、数据在本地。

## 五、失败模式与容错

| 失败模式 | 现象 | 容错策略 |
|---|---|---|
| 参数解析失败 | `fn.arguments` 不是合法 JSON | try/except 捕获, 提示模型重新生成 |
| 模型不调用工具 | 直接回答"我不知道" | 改进工具描述; 换工具调用能力更强的模型 |
| 工具抛异常 | MCP 返回 is_error | 把错误信息回传给模型, 让它换方案 |
| 循环不收敛 | 一直调用同一工具 | MAX_ROUNDS 上限 + 检测重复调用 |

生产级 Agent 需要完整的错误处理，教学版从简——理解调用链是第一目标。
